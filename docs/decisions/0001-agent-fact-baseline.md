# 0001：采用动态 Agent 事实基线

- 状态：accepted
- 日期：2026-08-27

## 背景

仓库曾要求每个源码模块对应一份本地 `docs/modules/` 文档，但整个 `docs/` 被 Git 忽略，已提交代码仍包含大量不存在的文档引用。根 README 和 Agent 指令也落后于已经实现的自由对话、画像、向量检索、CLI 和 token 用量功能。

逐文件镜像文档维护成本高，并不能保证 Agent 获取的是当前事实。Session 进度若只留在聊天上下文中，也无法在中断或换 Agent 后可靠恢复。

## 决策

- 使用根目录 `AGENTS.md` 作为唯一自动加载的工作契约。
- 使用少量按事实类型划分、由 Git 跟踪且可直接修改的核心文档，不建立逐文件镜像说明。
- 所有功能增删和行为变化在同一变更中同步受影响文档；高影响变更文档先行。
- 使用根目录 `progress.md` 保存会修改仓库的当前或最近一次 session 滚动快照，只在开始和结束或阻塞前更新。
- Session 结束时必须声明文档影响、验证与现场清理结果，并由本地脚本做结构校验。
- 不维护额外 Agent 工具入口；旧 `CLAUDE.md` 删除，避免双重规则漂移。

## 后果

- 新 Agent 可以从一个入口读取项目事实与最近交接，不依赖历史对话。
- 每次功能变更多出文档影响判断和收尾成本，但文档腐烂会更早暴露。
- `progress.md` 不能替代正式文档；新 session 覆盖前必须迁移长期信息。
- 本地检查只能验证结构和声明存在，不能证明语义完全正确；最终仍需 Agent 对照实现审阅。
