# EmailPet 项目事实基线

这里保存 Agent 和开发者共同维护的当前项目上下文。文档可修改、必须随实现演进，不作为旧版本归档使用。

## 阅读路由

| 文档 | 负责的事实 | 主要更新触发条件 | 代码证据入口 |
|---|---|---|---|
| [产品事实](product.md) | 产品定位、当前能力、用户边界、已知限制 | 功能增删、用户流程或产品边界变化 | `README.md`、前后端入口 |
| [架构与数据流](architecture.md) | 组件、Agent 图、生命周期、降级与安全边界 | 模块边界、图节点、数据流或故障策略变化 | `backend/emailpet/main.py`、`backend/emailpet/agent/` |
| [公共契约](contracts.md) | 配置、CLI、WebSocket、状态与持久化 | 字段、消息、命令、数据库职责变化 | `config.py`、`ws.py`、`cli.py`、storage |
| [开发与验证](development.md) | 环境、启动、测试、文档同步和清理流程 | 依赖、脚本、构建或交付流程变化 | `pyproject.toml`、`package.json`、`AGENTS.md` |
| [决策记录](decisions/README.md) | 重要选择及其原因和后果 | 跨模块、长期、难逆或安全相关决策 | 对应 ADR 与当前实现 |

会修改仓库的 session 还必须先读根目录 [`progress.md`](../progress.md)。它只保存当前或最近一次交接，不承载长期事实。

## 内容状态

- **当前事实**：代码和配置中已经存在的行为，应直接随实现改写。
- **已确认目标**：明确希望达到、但尚未完全实现的状态；不得与当前事实混写。
- **待决问题**：缺少产品决定、真实环境验证或实现证据的事项。

发现文档、代码、配置或测试互相冲突时，不静默选择一方：先确认当前可观察行为，再修正文档并把仍不确定的部分列为待决问题。

## 防腐规则

1. 功能新增、删除或行为变化必须同步检查全部受影响的事实文档。
2. 产品行为、架构、契约、配置、数据流和安全边界变化先写设计，再实现。
3. 每份事实文档只维护其负责的稳定信息，避免复制源码或其他文档全文。
4. 使用相对链接连接事实和证据；运行 `python3 scripts/check_docs.py` 检查结构与链接。
5. Session 结束时在 `progress.md` 明确列出更新过的文档，或说明无需更新的原因。
6. 长期原因进入决策记录；短期执行状态只进入 `progress.md`。
