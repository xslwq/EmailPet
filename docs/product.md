# 产品事实

## 当前事实

EmailPet 是一个本地运行的 AI Native 桌面邮件助手桌宠，不是完整邮件客户端。它通过 IMAP 查看新邮件，用 LLM 生成摘要并判断重要性，通过 Electron 桌宠界面或 CLI 与单个用户交互。

当前实现包含：

- 按配置间隔轮询 IMAP，并用 UID 存储避免重复处理。
- 对邮件进行摘要、重要性判断、分类和操作建议。
- 对不重要邮件自动归档并保留静默归档记录。
- 对重要邮件主动推送摘要，等待用户选择回复、归档或跳过。
- 回复必须先生成草稿，再由用户批准后通过 SMTP 发送；用户可以要求修改或拒绝。
- 用户修改草稿时，Agent 尝试提取称呼、签名、语气等偏好并写入本地画像。
- 可选配置 embedding；启用后为重要邮件建立本地向量索引，并提供带邮件检索的自由对话 Agent。
- CLI 可以启动服务、进行终端对话、查看用户画像、邮件统计、配置摘要和 token 使用情况。
- Electron 提供悬浮桌宠、重要邮件摘要、全文查看、意图选择和草稿审批界面。

## 核心用户边界

- 系统按单用户、单邮箱配置和单个活动 WebSocket 连接设计。
- 发送邮件属于外部副作用，必须经过草稿批准；归档重要邮件也需要用户选择。
- 不重要邮件会自动归档，这是当前已实现的主动副作用。
- 邮件正文、画像、checkpoint、用量和向量索引保存在本机 SQLite 文件中。
- 配置使用明文 YAML，凭据文件必须留在本地且不进入 Git。

## 已确认目标

- 保持“桌宠主动汇报、用户最终控制”的交互方式。
- 让 Agent 能利用本地邮件上下文回答问题，并逐步适应用户的回复风格。
- 项目事实文档始终描述当前有效行为，使新的 Agent 不依赖历史对话也能安全修改项目。

## 当前限制与待决问题

- 仓库没有可证明真实邮箱凭据环境下端到端联调成功的自动化证据；真实 IMAP、SMTP、LLM 与 Electron 联调仍需人工验证。
- 后端会发送 `chat_reply`，CLI 可以显示该事件，但 Electron renderer 当前没有处理它；桌面输入会发送 `user_say`，回复不会进入桌面消息列表。详见[公共契约](contracts.md)。
- embedding 维度固定为 1536，没有动态维度协商。
- 当前没有多账号、OAuth、附件操作、邮件搜索界面或完整收件箱管理能力。
- 自动归档策略是否需要更细的用户配置，尚无已确认产品决定。
